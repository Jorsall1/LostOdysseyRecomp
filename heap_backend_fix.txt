Switch 2: the heap backend (no mapping syscalls at all)
=======================================================
File changed: LostOdysseyRecomp/kernel/guest_address_space_switch.cpp (only .cpp, no headers)
Date: 2026-11-16

1. What early_boot.log proved
-----------------------------
    hints 0x73=0 0x74=0 0x75=0 0x77=0 0x78=0 0x15=1 0x51=0 0x52=0
    total=0x234000000  alias region=0xa96e00000+0x2000000000

Two boots died the same way:

    svcMapProcessCodeMemory (0x77)  -> process terminated (first boot)
    svcMapTransferMemory   (0x51)  -> process terminated (second boot)

with ReserveWindow() having already succeeded. Neither syscall is in the donor
title's NPDM syscall mask. A masked svc* on Horizon does not return an error
result - the kernel kills the process - so this cannot be detected or caught at
runtime, only avoided. The hint table says the same thing (only 0x15 set), and
0x73/0x74/0x75/0x78 are masked in the same way, which rules out every path that
makes memory appear at a chosen virtual address.

2. The new backend
------------------
Backend::Heap is now the only Switch 2 backend and issues zero SVCs:

    uint8_t* AllocateHeapWindow()          // memalign(0x1000, 0x100000000)
    {
        memalign(kPage, kSize)  -> one contiguous 4 GiB block
    }

This works because the whole design already treats the window as
`Memory::Translate(offset) == base + offset` (kernel/memory.h): every guest
address 0x00000000..0xFFFFFFFF is an offset into that block, so one heap block is
a complete window. The old code reserved a virtmem range and mapped chunks into
it; that machinery (ReserveWindow/MapChunk/MapView) is no longer called on
Switch 2 and the reservation is no longer created at all (s_reservation stays
null, which Allocate() now accepts for the heap backend).

Changes inside Allocate() on __SWITCH2__:
  * No ReserveWindow(), no virtmemFindAslr/virtmemAddReservation.
  * No ProbeProcessMemory(), no ProbeTransferMemory(): both are still compiled
    but unreferenced ([[maybe_unused]]), so the compiler drops them. The ELF now
    contains zero "probe process memory" and zero "probe transfer memory"
    strings, i.e. no call site for 0x77, 0x51 (or 0x15) exists in the boot path.
  * s_base = AllocateHeapWindow(); page-aligned and above the null page or the
    window is refused (the same placement guard as before).
  * s_backend = Backend::Heap; s_reservation is not required.

Commit() on the heap backend does no mapping and no syscall:
    start = chunk * kChunk; length = min(kChunk, kSize - start)
    memset(s_base + start, 0, length)   // memalign memory is uninitialized
    mark the chunk committed, count the bytes
The whole chunk is zeroed including the guest null page, so a null guest access
reads zeros exactly like the desktop hosts instead of faulting (plain heap
memory cannot be left permanently unmapped).

EnsureBacked() returns AlreadyBacked immediately on the heap backend: committed
heap pages cannot go missing, so the svcQueryMemory/repair path (and its
svcMapTransferMemory/svcMapProcessMemory calls) is never entered. This also
removes a per-XMA-buffer kernel query from the hot path.

3. What is lost with this backend (documented in code and here)
---------------------------------------------------------------
A (0xA0000000), C (0xC0000000) and E (0xE0000000) are now three ordinary ranges
of the same block instead of hardware aliases of one physical page. A write
through A is no longer visible through C or E, and E is no longer "A shifted by
one 4 KiB page". Everything that reaches guest memory through A keeps working:
  * recompiled code (all guest addresses are base + offset),
  * XMA (Physical() uses 0xA0000000 + p, i.e. A),
  * GPU copies and command-processor reads (physical A),
  * the unbacked-read repair path in patches/unbacked_guest_reads.cpp.
The guest paths that depend on real aliasing (data written through C/E and read
through A, or the one-page E shift) will see stale/zero data rather than crash.
Restoring true aliasing needs a mapping syscall, which the current NPDM mask
makes impossible; a donor title whose mask contains 0x74 would be required.
