DRIVER SOURCE (/tmp/ouncevk-src, nvkmd_nvgpu_native_completion.c)
  Status 8 = NVKMD_NVGPU_COMPLETION_HEALTH: the counter reached the target
  AND the batch's marker verified (the GPU did run the batch to its end), but
  the channel error notification (nvIoctl 0xc0104817) had a non-zero status.
  So the channel faulted, and the fault did not stop that batch's marker.
  The driver reads only the notification's status word; the error type
  (info32: 8 idle timeout, 13 GR exception, 31 MMU fault, 32 PBDMA error,
  ...) is dropped. Without it we cannot tell a bad memory access from a
  shader/graphics-engine exception or a bad command stream.
CHANGES
  * os/switch/ouncevk_channel_tap.c/.h (new, Switch 2 only), linked with
    -Wl,--wrap=nvIoctl (LostOdysseyRecomp/CMakeLists.txt, LO_TARGET_SWITCH2).
    Every nvIoctl call goes to the real one unchanged. When the health query
    returns a failure or a non-zero status, the first time only, it records
    the notification (fd, timestamp, info32, info16, status), sends one
    GetErrorInfo (0x80804816, NvError: type + 31 words) on the same fd and
    prints both to stderr.log as "[gpu channel] ...".
    If the stop comes without a health check (738 refusal, 793 refused
    submit), lo_ouncevk_channel_error() queries the last channel fd itself.
  * gpu/video.cpp StopGpuWork: on the first stop, runtime log lines
    "video: GPU channel error ... info32=N (name)" and "video: GPU channel
    error info ... type=..." or "GPU channel reports no error".
  * Checked in the ELF: the driver's nvkmd_nvgpu_native_channel_health calls
    __wrap_nvIoctl.
WHAT THE RESULT WILL TELL
  * 31 MMU fault: a GPU access to unmapped memory. Next suspects: a
    descriptor or vertex/index buffer pointing at memory freed while the
    menu was up (resources unused in the menu, freed, then used again on the
    first 3D frame), or the occlusion query buffers.
  * 13 GR exception: a shader or graphics engine error (bad state, a shader
    trap); look at the shaders and state of the first 3D frame.
  * 32 / 80 PBDMA: a bad command stream (driver side; report to OunceVK).
  * 8 idle timeout: a hang, not a fault.
  The error info words may also carry a fault address; we will compare it
  with the renderer's buffer and arena addresses.
