QUIT
  * Progress since turn 7: stderr.log now ends with "[exit] leaving through
    libnx's application exit on the main thread", so rule 1 (exit on the main
    thread) works. The donor game still closed with an error.
  * Cause found: RunExit pauses every other thread with svcSetThreadActivity.
    The loader's parkLeftThread pauses each left-over thread itself, and
    Horizon refuses to pause an already-paused thread (InvalidState, see
    Mesosphere KThread::SetActivity). The loader therefore counted every
    thread LO paused as "running, could not park" and called svcExitProcess.
    The turn-7 pause made parking impossible.
  * FIX (os/switch/switch_runtime.cpp):
      - ScanOtherThreads(true) records the paused handles (up to 256).
      - RunExit replaces the loader return address with
        envSetExitFuncPtr(&ResumeThenReturnToLoader). __libnx_exit ends in
        __nx_exit(0, envGetExitFuncPtr()), so this runs after __appExit (SD
        card unmounted, services closed), on the main thread. It resumes
        every paused thread (ThreadActivity_Runnable) and jumps to the
        loader, which can then park them.
      - Threads stay paused for the whole libnx teardown, as before. The only
        window in which they run against closed services is between the
        resume and the loader's own pause.
  * exit.log had never been written on the Switch 2: no exit.log or
    crash_report.txt on the card in any copy. RawAppend's private fsp-srv
    session apparently fails. FIX: RawAppend falls back to FsdevAppend, which
    uses libnx's own SD card FsFileSystem (fsdevGetDeviceFileSystem("sdmc"))
    with fsFs* calls only (no stdio, no locks). Boot now prints "[boot] own SD
    card session unavailable (rc ...)" to stderr.log when it fails.
