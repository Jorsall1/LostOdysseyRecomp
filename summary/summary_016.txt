ROOT CAUSE (kaiHEN source, /tmp/kaihen @ 9aa3716)
  * hen/README.md: libounce installs a clone of HEN's FS proxy root as the
    fsp-srv override and never sends SetCurrentProcess on it, "which would
    change the process identity that FS uses for every holder of the root".
  * LO's RawInitialize (switch_runtime.cpp, inherited from Switch 1, commit
    757b88e6) did smGetService("fsp-srv") -> that override (verified:
    smGetServiceWrapper returns the override handle, own_handle=0), then sent
    SetCurrentProcess (cmd 1, in_send_pid). HEN's own root then carried LO's
    process ID.
  * hen/source/game_arm.cpp: each armed launch opens
    "@Sdcard:/kaihen/bin/game/exefs.nsp" through that root
    (package_->open). With LO's process gone the open fails, restoreGate(rc,
    WaitProcess) lets the stock game load: "R starts the game normally" until a
    reboot gives HEN a fresh root. Matches every reported hook loss.
FIX (os/switch/switch_runtime.cpp, RawInitialize, __SWITCH2__ only)
  * fsOpenSdCardFileSystem() on libnx's fs session (a separate IFileSystem

    SetCurrentProcess. RawAppend unchanged. Switch 1 path unchanged.
  * Verified in the ELF: Initialize calls fsOpenSdCardFileSystem inline; no
    other SetCurrentProcess in LO (SDL hits are GDK-only files).
  NRO md5 fc076893a395f4b33b2e99d6b62ffc71 (Desktop copy matches). Build OK.
