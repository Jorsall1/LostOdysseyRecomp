WHAT TO LOOK FOR
  * "fence wait open N ms ... counter@X = V": V > threshold means the fence
    command did not run (or ran and something re-incremented).
  * Last fence events: is there an "enqueue" for counter X right before the
    hang, did its write pointer move, and is there an "execute" for it?
  * Ring: write == read with the enqueue's write-after != read means the
    rendering thread skipped it.
