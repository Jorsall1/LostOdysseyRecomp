FINDINGS
  1. "not completed" is not evidence of a hang: the ring marks a batch
     complete only in RecycleSlot, i.e. when its slot is reused two batches
     later. The newest accepted batch always reads "not completed". Turns
     43-51 treated it as a stuck GPU; it was not proven. Text changed to
     "completion not read yet".
  2. OunceVK (vulkan.o, disassembled): native_ctx_flush_locked calls
     native_ctx_prepare_batch -> nvkmd_nvgpu_native_batch_prepare_sources.
     Result 4 (header allocation failed) is handled by joining the oldest
     submission and retrying; any other non-zero result is the 738 line.
     prepare_sources returns
       1: bad arguments / a command range of size 0, not 4-aligned, over
          8 MiB, or the last range flagged (NVK no_prefetch), or more than
          2044 ranges, or wait words not a multiple of 5 / over 40,
       2: a command range outside the used part of every active span (the
          primary arena + active owner segments), or the new header block
          from the primary arena overlaps one of the batch's own ranges,
       3: total range bytes larger than the primary arena, or overflow,
       5: semaphore probe encode failed.
     Driver locking is global (one recursive mutex per native device for
     memory create/free and flush), so a pipeline-thread race is unlikely;
     turn 51's serialize lock added nothing. The arena allocator
     (alloc_reclaimable / recycle_live_record) looks correct. Which result
     the refused batches got is still unknown: the code is lost before the
     log line.
  3. Pattern across the stops: a heavy batch submitted when the previous one
     has finished (menu close, a new map's first frame). In steady 3D the
     previous batch is still in flight, which changes prepare_sources' path
     (w6 = previous point not complete -> extra wait words + header).
  4. Real bug on the crash path: TransferRegion uploaded its constants
     before Begin(). When it opens a batch (5203's first operation), Begin()
     recycles the slot and rewinds its upload ring to 0, so the batch's next
     uploads overwrote the transfer's constants (classes and scale). Wrong
     colours at worst; not shown to stop the GPU.
