CONCLUSIONS
  * Shader rewrites ([trim], [lean], early-Z) are not the cause: test B
    stopped the same way. (The [arena] clamp stays; it was on in both.)
  * PBDMA = the GPU's command fetcher rejected the command stream. A shader
    reading bad memory would be an MMU fault (31) or GR exception (13). So
    either the command data in GPU memory was wrong (overwritten, or not
    written back from the CPU cache), or the driver encoded a bad command.
    The 738 refusal (crash2) is the driver's own check of the same command
    ranges failing on the CPU side. Both point at the batch's command
    memory, on the first heavy batch after the menu.
DRIVER NOTES (/tmp/ouncevk-src)
  * NVK_DEBUG is read with getenv at instance creation; env.txt values are set
    before that. The ELF contains the options and vk_push_print.
  * push_sync (nvkmd.c nvkmd_ctx_exec): after every exec the driver syncs
    (flush + drain); if the exec or the sync fails it prints the exec's
    command buffer, decoded, to stderr (vk_push_print).
  * full_cmd_flush / full_arena_flush only widen cache flushes, and the
    native backend's mode-2 memory flush is just "dsb sy", so they test
    little. Not used.
