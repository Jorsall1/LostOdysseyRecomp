ROOT CAUSE FOUND: stale generator output
  * The XenonRecomp binary that made ppc/ (out/build/tools/..., 2026-11-16
    11:37:06, clang) predates the source it claims to come from
    (recompiler.cpp 11:56:54) and has no "non_volatile_in_context" support at
    all (string absent from the binary). ppc/ was generated with it at
    11:37:11. So, in the build that ran on the console:
    1. Every function in the toml's non_volatile_in_context list (190 of
       them) got r14-r31 as zeroed C++ locals: all MSVC __finally funclets,
       setjmp 0x82DF34A0, the hand-written codecs 0x82F8xxxx-0x8312xxxx,
       and the callers host hooks read (sub_82AD6088 for
       cinematic_bars at 0x82AD616C, battle_script_timer, asset_failure,
       occlusion_history). Turn 21's heap-lock leak and turn 29's 25
       "funclets reading zeroed registers" are this one bug.
    2. CRT memset sub_82B7BC40 was cut at 0x82B7BCD0: for a count with
       (n & 3) == 2 or 3 it wrote only the first trailing byte and returned
       (the rest went into stub functions nothing calls). Any memset with
       such a size left 1-2 bytes of old data.
    3. fast_memory and argument_as_local from the toml were not applied.
  * Upstream / Switch 1 builds use the current generator, which is why the
    same game code works there.
